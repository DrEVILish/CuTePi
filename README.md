# CuTePi

CuTePi is a cue-based show playback controller for the Raspberry Pi. It plays video, images and audio full-screen on
HDMI from a cue list run in a web browser, with fades, crossfades, layers, scheduling, a panic holding image, and
remote control from Bitfocus Companion (HyperDeck and QLab).

- **Design:** [DESIGN.md](DESIGN.md) — product decisions, architecture, playback engine, remote protocols.
- **Test results:** [TEST_REPORT.md](TEST_REPORT.md) — system test rounds, measurements, open findings.
- **Servers:** [AGENTS.md](AGENTS.md) — the test (Pi 4) and dev machines and how to test on them.
- **Codec test tools:** [tools/codec-corpus/](tools/codec-corpus/).

## Running as a service

On the Pi, from the checkout in `/opt/cutepi` (binary built there):

```
sudo deploy/install-service-user.sh
```

It creates the unprivileged `cutepi` system user, installs the polkit rules (`deploy/50-cutepi.rules`) and the unit
(`cutepi.service`), copies existing data from `/root/cutepi` into `/var/lib/cutepi` (keeping the original), and
restarts the service. See DESIGN.md §7 for what the service user is allowed to do and why.

## Codec support

CuTePi is meant to play **any codec GStreamer can decode**: hardware decoders are fast paths, never the supported
set. Every codec has its own test, and this table is regenerated after each batch of testing.

**Supported** means, measured on the hardware named below through the live service:

- **Video:** a 1080p60 file plays at 60 fps — a new frame on at least 59 of every 60 refreshes — during a 1 s fade
  in, steady play and a 1 s fade out, and both fades change the opacity at least 59 times a second (a smooth fade at
  the display rate).
- **Images:** a 1080p still fades in and out with the opacity changing at least 59 times a second.
- **Animated images** (GIF, APNG, WebP): as images, and every frame of the animation is presented at the file's own
  timing (all but at most one frame per 0.9 s measuring window, as 59 of 60 for video) through the fades and steady
  play. GIF cannot store 60 fps (its frame
  delays are in 1/100 s), so animated images are tested at 25, 30 and 50 fps.
- **Transparency** (files named `*_alpha`, video and images): as above, and the picture reaches the display with its
  alpha channel, blended as straight (non-premultiplied) alpha, so transparent areas show what lies beneath.
- **Audio:** (the 1080p60 part does not apply) the HDMI audio stream runs without a break through steady play and
  the fade out.

Anything else is listed as **"&lt;Pi model&gt; - unsupported"**, with what was measured. Every video codec is tested in
both **MOV** and **MKV** wherever the container can carry it.

How it is measured: [tools/codec-corpus/support.py](tools/codec-corpus/support.py) uploads each file of the support
set ([make-support.sh](tools/codec-corpus/make-support.sh)), plays it as a cue with the fades, and counts what the
display actually latched per refresh with kernel tracing (frames committed to the display, opacity writes, vblank
timing), from outside the service. To refresh the table, on the Pi:

```
tools/codec-corpus/make-support.sh
python3 tools/codec-corpus/support.py --readme README.md
```

### GPU compositor wall (in development, `CUTEPI_WALL=gl`)

The same support set through the GPU compositor wall (DESIGN §6.1.1), which is not the default yet. Here every layer
is blended by the GPU and the display shows one finished picture per refresh, so the test reads the wall's own
counters of frames actually put on screen (`GET /api/debug/glwall`) instead of tracing display planes. Fades change
the opacity on every refresh when the CPU is free. Software codecs mostly play faster than on the plane wall,
because late frames are shown and the decoder skips ahead to stay in step with the sound. The table below dates from
2026-10-03; since 2026-10-07 the wall's threads run real-time (SCHED_FIFO) and H.264 1080p60 plays at 59.6–60.1
(TEST_REPORT, "Performance round, 2026-10-07"), so its H.264 rows are out of date until the next full run. To refresh
this table, run the service with `CUTEPI_WALL=gl` and:

```
python3 tools/codec-corpus/support.py --section gl --readme README.md
```
