## Findings and follow-up

| Severity | Location | Evidence |
|---|---|---|
| Warning | gsp/audiobus.go:317, audioBusRelease | Disconnecting a streaming input can post an interaudiosrc not-linked error. Observed in the service journal and reproduced in all three CT stress runs. Audible impact was not independently captured. |
| Critical | BCM2835/MMAL decoder lifecycle; gsp/gsp_warm.go preroll/retirement | Experimental builds experienced decoder preroll/GO stalls and kernel component-create/stream-off failures. Process restarts did not recover the wedged decoder; stock boots did. The causal role of the audio changes versus decoder lifecycle remains unproved. |
| Warning | gsp/gsp_warm.go:74 and gsp/gsp.go:902 | A six-second warm-build wait can expire while that build/retirement still owns a decoder, followed by a cold build of the same cue. Source inspection establishes the overlap risk; it is not a proven explanation of the kernel fault. |
| Warning | gsp/gsp_warm.go:219 | An in-flight WarmNext can publish after Panic because final installation has no halt/generation validity check. This was identified by independent source review, not isolated by this hardware run. |
| Warning | Original live-page standby startup | WebKit emitted cache database/table/lock warnings when the original show started. Live-page behavior was not qualified in this file-focused run. |

The audio candidates passed CT tests but did not qualify on the Pi. They remain on the local investigation/audio-teardown-20261115 branch; main's application source was restored to c98ea65. The [diagnostic test patch](artifacts/2026-11-15-hardware/audio-diagnostic-tests.patch) is a zero-context reproducer (apply/check with git apply --unidiff-zero), not an enabled test or an accepted fix.

The first SDK rebuild also changed explicit compiler flag recording. Checking go env confirmed that the original effective default already used -O2; no optimisation-cause claim is supported. Build configuration and source changes must be controlled independently in follow-up.

## Limits and restored state

- Presenter counters are application evidence. Scanout images independently establish picture content, not every optical frame or zero missing opening frames.
- HDMI ALSA was RUNNING, but no independent speaker/audio capture was available. Audible onset, lost audio samples and end-to-end A/V offset remain unverified.
- The <50ms physical picture-and-sound target remains unqualified. No threshold was relaxed.
- Resource samples are in the raw results; this short run is not a show-duration leak/soak gate.
- Saved cues, groups and selection were compared exactly against the backup after restoration; the original36 media records remain and all temporary media records/files were removed.
- The final service is active; the hardware-test lock is released. Its source and binary match the tested architecture application code.
- Three normal boots cleared the transient mesh: eth0 remains UP at192.168.10.73, wlan0 is DOWN/managed and bat0 is absent. No network configuration or controller was changed. The assigned TimerPi network owner was notified; restoration remains subject to the existing shared-slot/profile agreement. See [canonical allocation](../SHARED_PI_ALLOCATION.md).
